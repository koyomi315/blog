大模型、Agent、Tool、Function Calling、MCP 和 Skills 经常在同一段讨论中出现，但它们解决的问题并不相同。理解这些边界，是设计 Agent 系统的第一步。

## 从大模型开始

大语言模型接收一段上下文，并根据上下文预测后续 Token。一次请求中的上下文通常包括：

- 系统指令；
- 用户消息；
- 历史对话；
- 工具定义和工具执行结果；
- 应用补充的环境信息。

模型本身不会自动记住上一次 API 请求。聊天产品表现出的“记忆”，通常由应用保存历史信息，并在后续请求中重新组织进上下文。

这也解释了两个工程问题：上下文会逐渐变长，而真正重要的信息可能被噪声淹没。因此，Agent 不仅要调用模型，还要负责上下文选择、状态保存和压缩。

## Agent 比一次模型调用多了什么

一个最小 Agent 通常包含四部分：

1. **模型**：理解任务并决定下一步；
2. **工具**：读取文件、访问服务或执行操作；
3. **状态**：保存对话、任务进度和环境信息；
4. **执行循环**：不断在“思考—调用—观察”之间迭代，直到完成或停止。

普通问答一般是一次输入对应一次输出；Agent 则可能在一次用户任务中触发多轮模型调用和多次工具执行。

## Tool：连接外部世界

模型只能处理输入并生成输出。要读取数据库、调用搜索、写文件或执行命令，应用需要把这些能力包装成工具。

一个可用的工具定义至少需要：

- `name`：稳定、清晰的工具名称；
- `description`：说明工具能做什么、何时应该使用；
- `parameters`：参数名称、类型、必填项和约束；
- 实际执行函数：由应用运行，模型不能直接看到实现。

工具描述会直接影响模型能否正确选择工具。描述“搜索内容”过于模糊；描述“在当前仓库中按正则表达式搜索文本，并返回文件、行号和匹配行”则更容易得到稳定调用。

### 工具也需要风险分级

可以按副作用划分工具：

| 等级 | 例子 | 常见策略 |
|---|---|---|
| 只读 | 搜索、读取、状态查询 | 通常可以自动执行 |
| 可逆写入 | 修改草稿、创建临时文件 | 限定目录并记录变更 |
| 外部写入 | 发消息、更新工单、修改数据库 | 明确目标并考虑人工确认 |
| 高风险执行 | 删除、支付、生产变更 | 强约束、审批和审计 |

安全的关键不是禁止工具，而是让权限与影响范围匹配。

## Function Calling：模型与工具的约定

Function Calling 不是工具本身，而是模型和应用之间描述工具调用的结构化约定。一次典型流程是：

1. 应用把可用工具定义发给模型；
2. 模型返回工具名和结构化参数；
3. 应用校验参数并执行对应函数；
4. 应用把工具结果作为新消息返回给模型；
5. 模型依据结果继续回答或发起下一次调用。

工具参数即使由模型生成，也不能直接信任。应用仍需要做类型校验、权限判断、路径限制、超时和错误处理。

## MCP：标准化工具和上下文接入

当每个 AI 应用都使用自己的工具协议时，同一个数据源需要重复适配。Model Context Protocol（MCP）尝试把连接方式标准化。

可以从三类角色理解 MCP：

- **Host**：面向用户的 AI 应用，负责整体调度和权限；
- **Client**：Host 内部与某个 Server 建立连接的组件；
- **Server**：对外提供工具、资源或提示模板的独立服务。

MCP 解决的是“能力如何被发现和调用”，并不替代应用自己的业务授权。Server 声明了一个删除工具，不代表 Host 应当允许模型自动执行它。

MCP Server 常见的能力包括：

- **Tools**：可以执行的操作；
- **Resources**：可读取的数据或上下文；
- **Prompts**：可复用的提示模板。

## Skills：把方法沉淀为可复用流程

Skills 更接近“如何完成一类任务”的操作手册。它可以规定：

- 什么时候启用；
- 开始前要读取哪些资料；
- 按什么步骤执行；
- 使用哪些工具；
- 如何验证完成结果。

工具提供原子能力，Skill 组织这些能力。比如“读取文件”和“运行命令”是工具，而“创建并验收一个 Word 文档”是一套包含读取模板、生成、渲染和视觉检查的 Skill。

## 它们如何协作

```text
用户目标
  ↓
Skill 选择工作流程
  ↓
Agent Loop 决定下一步
  ↓
Function Calling 产生结构化调用
  ↓
本地 Tool 或 MCP Server 执行能力
  ↓
结果进入上下文，继续下一轮
```

这个结构中，每一层都可以单独改进：模型负责决策质量，工具负责执行质量，协议负责互操作，Skill 负责流程复用，Agent Runtime 则负责状态、权限和循环控制。

## 总结

判断一个概念属于哪一层，可以问三个问题：

- 它是在做决策，还是在执行动作？
- 它定义的是通信格式，还是任务方法？
- 它保存的是模型上下文，还是外部系统状态？

把这些边界分清后，Agent 系统会更容易测试和演进：工具失败不必归因于模型，流程不稳定也不必全部塞进提示词。
