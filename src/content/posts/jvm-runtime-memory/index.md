JVM 内存问题经常被简化成“栈放局部变量、堆放对象”，但真正排查异常时，还需要理解栈帧、类元数据、直接内存和类加载之间的关系。

## 线程私有区域

### 程序计数器

每个线程需要记录下一条要执行的字节码位置。线程切换后，JVM 可以据此恢复执行。

它占用空间很小，也是 JVM 运行时数据区中通常不会报告 `OutOfMemoryError` 的区域。

### Java 虚拟机栈

每次 Java 方法调用都会创建栈帧。栈帧通常包含：

- 局部变量表；
- 操作数栈；
- 动态链接信息；
- 方法返回信息。

递归过深或单线程栈需求超过限制时可能出现 `StackOverflowError`。栈容量和线程数量也会共同影响进程内存。

局部变量表中可以保存对象引用，但对象本身通常分配在堆中。“引用在栈、对象在堆”只是常见情况，具体优化仍由 JVM 实现决定。

### 本地方法栈

本地方法栈支持 JNI 等本地方法执行。规范层面它与 Java 虚拟机栈概念不同，具体实现可能采用统一或不同的管理方式。

## 线程共享区域

### 堆

堆是对象实例和数组的主要分配区域，也是垃圾收集器管理的核心。

常见收集器会按对象年龄、区域或回收目标组织堆，但“年轻代 + 老年代”的具体布局不是所有收集器都以同样方式实现。分析日志时应结合当前收集器，而不是只套固定内存图。

堆无法继续满足分配需求且回收无效时，会出现 `OutOfMemoryError: Java heap space`。

### 方法区与元空间

方法区是 JVM 规范中的逻辑区域，用于保存类结构、运行时常量池、方法和字段信息等。

HotSpot 在较新版本中使用元空间实现主要的类元数据存储，并从本地内存分配。方法区是规范概念，元空间是具体实现，二者不能简单画等号。

大量动态生成类、类加载器泄漏或元空间上限过小，可能导致 `OutOfMemoryError: Metaspace`。

### 运行时常量池

类文件的常量池包含字面量和符号引用。类加载后，相关内容进入运行时常量池，符号引用会在解析过程中转为直接引用。

字符串常量池与类运行时常量池相关但不完全相同。讨论它们的位置时必须注明 JDK 与 JVM 实现版本，不能沿用早期永久代的结论解释所有现代 JVM。

## 直接内存

直接内存不属于 JVM 运行时数据区，但 NIO、网络库和本地组件可能大量使用它。它减少某些 Java 堆与本地 IO 之间的复制，却也让内存问题更难只通过堆使用量观察。

直接内存不足时可能出现 `OutOfMemoryError: Direct buffer memory`。排查时要同时观察进程常驻内存、直接缓冲区和本地库。

## 对象创建的大致过程

执行 `new` 时，JVM 通常需要：

1. 确认类已经加载、链接和初始化到适当阶段；
2. 为对象分配内存；
3. 初始化对象头和字段零值；
4. 执行构造逻辑；
5. 把引用返回给调用方。

分配可能通过线程本地分配缓冲区完成，以减少多线程同时在堆上分配的竞争。大对象、缓冲区耗尽或特定收集器配置会走不同路径。

## 类加载生命周期

一个类从字节码到可用状态通常经历：

```text
加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载
```

- 加载：根据名称获取字节码并创建类的运行时表示；
- 验证：检查字节码和结构是否合法；
- 准备：为类变量分配空间并设置初始零值；
- 解析：把符号引用转换为直接引用；
- 初始化：执行类初始化逻辑。

解析可能在不同时间发生，不能把这个序列理解成所有步骤都严格一次性连续完成。

## 双亲委派解决什么

类加载器收到加载请求时，通常先委托父加载器，父加载器无法完成才由自己尝试。它有助于：

- 避免核心类被重复加载；
- 保持类身份和基础类型的一致性；
- 降低用户代码替换平台核心类的风险。

应用服务器、模块系统和插件框架可能采用更复杂的加载策略，因此排查 `ClassNotFoundException`、`NoClassDefFoundError` 或类型转换异常时，需要同时检查类名与类加载器身份。

## 常见错误如何对应区域

| 错误 | 常见方向 |
|---|---|
| `StackOverflowError` | 递归、过深调用链、过大栈帧 |
| `Java heap space` | 对象持续增长、堆过小、内存泄漏 |
| `Metaspace` | 动态类过多、类加载器泄漏 |
| `Direct buffer memory` | 直接缓冲区未释放或上限不足 |
| 无法创建本地线程 | 线程数、单线程栈、本地内存或系统限制 |

错误名称是排查入口，不是根因结论。仍需要结合堆转储、线程转储、GC 日志和本地内存指标。

## 总结

JVM 内存由多个生命周期和所有权不同的区域组成。栈与方法调用相关，堆承载主要对象，方法区描述类，直接内存服务本地 IO，而类加载器决定类元数据能否卸载。把异常放回对应区域，排查才不会停留在“加大堆”这一种手段上。
