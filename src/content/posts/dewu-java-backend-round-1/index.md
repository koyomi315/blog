## 二、自动定时评测、Trace 与评分器

2. 自动定时评测需求的主要难点是什么？
   - 当时回答：重点是保障长链路异步任务的可靠执行、正常状态流转，以及异常重试和失败状态收敛。
3. 介绍自动定时评测的整体流程。
   - 当时回答：外部定时触发后，按时间窗口收集 Trace、构建测试集，再执行评测，最后将低于阈值的 Trace 归集为 Bad Case，供人工筛选、检查。
   - 回答中更正过：这里直接评测线上的历史 Trace，不进行 Agent 重放。
4. 追问：定时任务如何调度和触发？
   - 当时回答：外部定时平台每分钟调用扫描接口；接口扫描数据库中的任务配置，为到期任务创建执行。
5. 追问：线上 Trace 如何采集，时间窗口如何确定？
   - 当时回答：根据任务的计划执行时间和配置的回溯时长计算窗口，再分页查询。例如中午触发、收集过去六小时的数据。
6. 追问：Trace 存在哪里，数据结构和字段是什么？
   - 当时回答：使用 MongoDB。提到存储结构分三层，但只展开了基础资产记录，包括 ID、所属 Agent、时间等，用于平台列表展示；其余层次没有完整讲出。
7. 如何评测 Trace，使用什么评分器？
   - 当时回答：提前配置评分器，分为代码评分器和大模型评分器；前者执行代码得到结果，后者通过 Prompt 约束评分。
8. 追问：评分维度如何设计，有哪些具体指标？
   - 当时回答：当时主要做基础平台，没有专门设计一套业务评分标准，而是复用 Langfuse 相关评分器。举了简洁性的例子，其他具体指标记不清。
9. 定时任务的幂等性如何实现？
   - 当时回答：用任务 ID 与计划执行时间构成业务幂等键，并建立唯一索引，避免重复触发时为同一执行点创建多次执行。

## 三、Tool Mock

10. Tool Mock 的 fixture 如何精确匹配？
    - 当时回答：首先根据 Agent、Tool 路由到真实工具、平台通用 Mock 或业务方提供的 Mock 服务。
    - 通用 Mock 按 Agent、测试集、Case、Tool 和工具入参匹配结果；先通过哈希值定位记录，再复核具体值。

## 四、OnCall Agent 与 RAG

11. OnCall Agent 使用什么开发框架，为什么选择它，有没有对比其他框架？
    - 当时回答：使用 Spring AI Alibaba，希望用 Java 实践 Agent。选型时没有系统对比，主要是个人判断其使用较多、比较成熟。
12. ReAct 的循环逻辑是什么，如何结束并避免死循环？
    - 当时回答：将 Query 交给模型；模型返回工具调用时执行工具，将结果补回上下文后继续请求模型。没有工具调用时结束，另外设置执行时长、最大轮数限制。
13. ReAct 与 Plan-Execute 有什么关系，Planner 和 Executor 如何协作？
    - 当时回答：将 ReAct 理解为单 Agent 架构，将 Plan-Execute 理解为多 Agent 架构；Planner 负责规划，Executor 执行并返回结果。Planner 可以将 Executor 当作工具，根据执行结果继续细化规划。
14. RAG 文档如何解析、分块？
    - 当时回答：自己使用 Markdown，认为不需要额外文档解析；PDF 等其他格式先转为文本。分块按 Markdown 标题等语义结构处理，同一结构内再按窗口划分。
