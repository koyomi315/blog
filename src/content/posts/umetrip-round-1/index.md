## 一、自我介绍与技术栈

1. 请做一下自我介绍，介绍实习经历与主要工作。

## 二、Java 集合与 JVM

3. Java 中 `==` 和 `equals` 有什么区别？
   - 当时回答：对象引用使用 `==` 时比较地址，`equals` 可以通过相应实现进行值比较。
4. 方法重载与重写有什么区别？怎样判断方法是否构成重载？
   - 当时回答：重载是在同一个类中，同名方法通过不同入参提供不同实现；重写涉及子类对父类方法的重新实现。进一步解释重载时提到了参数数量、参数类型和“返回参数”，当时表述不够清楚。
5. ArrayList 和 LinkedList 的底层结构及适用场景有什么区别？
   - 当时回答：ArrayList 基于数组，LinkedList 基于链表。从查找、插入和元素移动的角度比较，认为数组查找更快、对二分查找支持更好，链表插入不需要移动后续元素。现场主要停留在这些概括，没有进一步区分具体操作条件。
6. 是否了解 ConcurrentHashMap？
   - 当时回答：只是大概听说过，理解为适合并发处理的 Map，没有深入展开。
7. JVM 的运行时内存区域有哪些，分别存放什么？
   - 当时回答：提到了程序计数器、栈、堆和方法区，解释栈帧对应一次方法调用，方法区保存类相关信息。描述堆时提到了“全局变量、对象相关信息”，其余区域一时没有想起来。
8. JVM 中哪些区域线程私有，哪些线程共享？
   - 当时回答：栈和程序计数器线程私有，堆与方法区线程共享，没有完整展开其他区域。
9. JVM 不同内存区域中，哪个不容易发生 OOM？为什么？
   - 当时回答：选择程序计数器，认为它主要记录当前执行位置，是比较具体且受程序控制的值；与调用过多导致栈溢出、类加载较多的情况作了对照。现场解释仍带有“不太可能”的不确定语气。

## 三、Agent 评测平台与业务背景

10. 你对哪些实习或项目经历更熟悉？
    - 当时回答：实习发生得较近，对其中的 Agent 项目更熟悉。
11. 线上 Trace 是什么，包含哪些数据？
    - 当时回答：记录一次 Agent 运行过程，包括输入输出、大模型生成的文本、工具调用请求和结果，以及 RAG 检索请求和结果，以 JSON 形式组织。
12. 之前如何获取、筛选 Trace？自动定时评测如何改变这个流程？
    - 当时回答：业务 Agent 接入 Langfuse 收集 Trace，评测平台再同步这些记录。之前由人工挑选表现不好的 Trace 加入测试集；自动定时评测按时间窗口收集 Trace，评分后归集低分 case。
13. 自动定时评测有什么业务价值？相比人工筛选，为什么要这样做？
    - 当时回答：面对大量历史 Trace，先让较信任的大模型粗筛，再由人工进一步筛选低分 case，希望减少逐条查看的人工成本。自动流程主要包括收集、评分和低分归集。

## 四、消息队列、异步任务与幂等

14. 是否用过或了解 RocketMQ 等消息队列？DDMQ 是怎样工作的？
    - 当时回答：被问及的其他消息队列没有用过，只介绍了实习中使用 DDMQ 的理解。另一种被问及的消息队列名称未记录。
15. 任务持久化、消息队列和 Worker 如何配合完成任务派发与申领？
    - 当时回答：任务内容和状态保存在数据库中，消息主要携带任务 ID。任务中间件先创建记录，再通过 DDMQ 派发；Worker 获取 ID 后，通过中间件完成任务申领。
16. 自动定时评测的完整执行流程是什么？如何解决重复触发和多 Worker 并发申领？
    - 当时回答：配置定时任务并保存，外部类似 cron 的平台每分钟调用接口，检查到期计划并创建执行，之后依次收集 Trace、评分、归集低分 case。
    - 重复触发：以“任务 ID＋计划时间”建立联合唯一索引，避免同一计划时间重复创建执行记录。
    - 并发申领：使用 CAS 思想，按预期前置状态进行条件更新；已被其他 Worker 申领的任务，不再满足更新条件。
17. revision 和 CAS 是否需要同时使用？只用其中一个能否完成状态迁移或并发控制？
    - 当时回答：没有解释清楚，表示需要下去再思考。
18. 任务失败、消息补发和异步状态收敛如何处理？重试如何保证幂等？
    - 当时回答：在时间和重试次数限制内尝试补发；扫描实际工作状态，发现评分已结束但记录仍在执行中时，推进到低分归集阶段。也提到重试需要设计幂等性。
19. MongoDB 用的是集群还是单点部署？
    - 当时回答：印象中似乎是单点，没有给出确定的部署信息。
20. 如何保证幂等性？幂等键如何设计？
    - 当时回答：使用“任务 ID＋计划时间”区分每次执行。同一天同一计划时间多次重试只创建一条执行记录，第二天的同一时刻则对应另一条记录。
21. MongoDB 中如何实现“存在则返回已有记录，不存在则创建”？怎样防止重复创建？
    - 当时回答：模糊描述了已有记录则返回、没有则创建的能力，强调仍需幂等键；没有说明具体接口和完整实现细节。

## 五、Tool Mock 与评测重放

22. Tool Mock 服务解决什么问题？如何匹配返回结果，Mock 数据从哪里来？
    - 当时回答：评测重放时，用历史工具调用结果替代真实工具调用，以保证评测可重复。依据数据集 ID、case ID、工具及入参匹配结果；素材从历史 Trace 中提取。
23. 线上评测与离线评测有什么区别？Tool Mock 用于哪种场景？
    - 当时回答：线上评测直接对已有真实 Trace 评分；离线评测把测试集输入重新交给业务 Agent，获得新的运行结果后再评分。Tool Mock 用于离线重放。
24. 业务 Agent 如何接入 Tool Mock？如何选择真实工具、平台 Mock 和业务自建 Mock？
    - 当时回答：需要业务 Agent 改造工具调用，根据请求中的信息和平台配置，选择真实工具、平台提供的 Tool Mock 或业务方自建 Mock，没有展开具体接入协议。
25. Mock 匹配失败怎么办？有没有降级策略，会回退调用真实工具吗？
    - 当时回答：没有匹配到历史结果时，返回 Mock 失败及其原因，不回退调用真实工具。当时没有进一步的降级策略。

## 六、实习困难与 AI 辅助开发

26. 实习遇到过什么困难，如何解决？怎样与同事沟通、反馈进度？
    - 当时回答：曾低估需求工作量，认为有 AI 辅助就能较快完成，承诺周五上线，实际推进时才发现业务理解和实现细节上有很多问题。之后增加投入，借助 AI 理解平台，并向同事核对业务、技术方案和问题排查方向。
    - 现场复盘：早期与同事沟通较少，后来意识到应及时反馈进度和卡点，让同事了解当前状态并提供帮助。
27. 平时使用哪些 AI Coding 工具？
    - 当时回答：最近使用 Codex 较多，实习期间也尝试过其他编程工具，会关注和试用不同工具。其余工具名称未完整记录。
28. 面对新项目，如何借助 AI 理解项目和代码？
    - 当时回答：先让 AI 介绍整体功能和主要模块，建立初步认识；再聚焦需要实现需求的模块，一边听讲解，一边对照源码逐步理解。
29. 使用或编写过 Skill 和 MCP 吗？用它们做过什么？
    - 当时回答：将秋招期间整理面经、上传博客等固定工作流做成 Skill，减少重复说明工具与步骤。MCP 更多由 AI 根据任务推荐使用，自己主动指定得较少，也没有编写过 MCP 服务。
