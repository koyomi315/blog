## 二、HashMap 与并发

3. 什么样的对象可以作为 HashMap 的 key，需要满足什么条件？
   - 当时回答：从能否计算哈希码出发，说明需要对 key 做哈希运算，再定位到桶；没有进一步展开其他条件。
4. HashMap 的底层结构与 put 流程是什么，如何处理冲突和相同 key？
   - 当时回答：底层是数组加链表或红黑树，数组承担桶的作用。计算 key 的哈希值并定位桶，空桶直接插入；已有元素时判断是相同 key 还是哈希冲突，相同 key 覆盖值，否则放入对应链表或树中。冲突较多时，红黑树有利于查找。
   - 追问：HashMap 是否线程安全，并发 put 可能有什么问题？
     - 当时回答：不是线程安全的，多个线程同时向同一桶添加元素，可能只保留其中一次写入。
   - 追问：并发场景如何使用 Map，synchronized 与 ConcurrentHashMap 有何差别？
     - 当时回答：可以对整个 HashMap 对象加互斥锁，或使用 ConcurrentHashMap。当时将后者理解为对同一个桶的操作加锁，锁粒度更细，并发效率更高。

## 四、MySQL 索引

7. MySQL 索引为什么使用 B+ 树，与哈希、二叉搜索树相比有什么优势？
   - 当时回答：哈希适合按键快速查找，但不便范围查询；B+ 树层高较低，可以减少磁盘 I/O。非叶子节点用于索引，记录保存在叶子节点，查询路径较稳定；叶子节点通过类似链表的结构串联，便于范围查找。
   - 追问：什么是回表，使用非聚簇索引时为什么可能需要回表？
     - 当时回答：如果需要的字段不在所建联合索引中，就要再到聚簇索引查找这些字段。
   - 追问：怎样避免回表？
     - 当时回答：根据业务经常查询的字段组合构建索引，让需要查的字段都包含在索引中。
