Spring 的核心价值不是减少 `new` 关键字，而是把对象创建、依赖关系、生命周期和横切能力交给容器统一管理。

本文依据 Spring Framework 官方参考文档核对核心概念。

## IoC 容器管理什么

由 Spring IoC 容器创建、组装和管理的对象称为 Bean。容器根据配置元数据知道：

- 哪些类需要实例化；
- Bean 之间如何依赖；
- 使用什么作用域；
- 初始化和销毁时执行什么；
- 需要应用哪些后置处理和代理。

配置可以来自注解、Java 配置或其他元数据形式。关键不是形式，而是依赖关系由外部容器装配。

## 构造器注入优先表达必需依赖

构造器注入让必需依赖在对象创建时就完整：

```java
@Service
public class OrderService {
    private final OrderRepository repository;

    public OrderService(OrderRepository repository) {
        this.repository = repository;
    }
}
```

它的优点是：

- 字段可以保持 `final`；
- 对象不会处于“创建完成但依赖未注入”的状态；
- 单元测试可以直接传入替身；
- 构造参数过多会及时暴露职责膨胀。

可选依赖可以使用显式配置或 Setter，但不应把所有依赖都隐藏在字段注入中。

## `@Component` 与 `@Bean`

组件扫描适合自己维护的应用类：

- `@Component`：通用组件；
- `@Service`：业务服务语义；
- `@Repository`：数据访问语义；
- `@Controller`：Web 控制器语义。

`@Bean` 方法适合第三方类或需要显式构造过程的对象。两种方式最终都是向容器注册 Bean 定义。

## Bean 默认单例意味着什么

默认 singleton 作用域表示一个 Spring 容器中通常只有一个 Bean 实例，不等同于整个 JVM 永远只有一个对象。

单例 Bean 会被多个请求线程共享，因此不应把请求相关的可变状态保存在普通字段中。无状态服务天然更适合默认作用域。

## 声明式事务依赖代理

`@Transactional` 常通过 AOP 代理拦截方法调用：

```text
caller → transaction proxy → target method
```

代理在方法前开启或加入事务，正常返回时提交，符合回滚规则的异常时回滚。

这带来一个重要边界：同一个对象内部直接调用自己的事务方法，调用可能没有经过代理，因此事务增强不会按预期触发。

```java
public void outer() {
    inner(); // 普通的 this 调用
}

@Transactional
public void inner() {
    // 可能没有经过事务代理
}
```

解决思路是重新划分服务边界，让调用经过另一个 Bean，而不是为了绕过设计去获取自己的代理。

## 事务传播解决嵌套边界

业务方法互相调用时，需要决定加入现有事务、创建新事务还是禁止事务。传播行为描述的就是这种关系。

使用前要问：

- 内层失败是否应该回滚外层；
- 内层是否必须独立提交；
- 外层没有事务时是否允许执行；
- 新事务是否会额外占用数据库连接。

传播配置不是越复杂越好。大多数业务从清晰的单事务边界开始更安全。

## 回滚规则

默认回滚规则与异常类型有关。业务异常体系如果设计不当，可能出现方法抛错但事务已经提交。

同时，捕获异常后仅记录日志而不继续抛出，也会让事务代理认为方法正常完成。是否回滚应成为明确业务设计，而不是依赖偶然异常路径。

## Spring Boot 自动配置

Spring Boot 根据 classpath、已有 Bean 和配置属性，按条件注册常见基础设施。它解决的是大量重复配置，而不是跳过 Spring 容器。

可以把自动配置理解为一组带条件的普通配置：

- 依赖存在时才生效；
- 用户没有自定义 Bean 时提供默认 Bean；
- 配置属性满足条件时启用；
- 用户定义优先覆盖合理默认值。

排查自动配置时，应查看条件评估结果和实际 Bean 来源，而不是只猜注解展开后的行为。

## 常见边界

- 在单例 Bean 字段中保存请求状态；
- 事务方法自调用；
- 事务中执行长时间外部网络请求；
- 捕获异常后静默返回；
- 一个 Bean 同时承担过多职责；
- 用循环依赖掩盖错误的模块关系。

## 总结

IoC 让对象关系显式交给容器，依赖注入让对象保持可构造和可测试，AOP 代理提供事务等横切能力，自动配置则减少基础设施样板代码。理解代理边界和 Bean 生命周期，比只记注解列表更重要。
