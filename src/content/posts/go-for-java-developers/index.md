Java 开发者学习 Go 时，语法通常不是最大障碍。真正需要调整的是对象模型、错误处理和并发方式。

## 从包和函数开始，而不是类层次

Go 用包组织代码，结构体承载数据，方法可以绑定到自定义类型。它没有 Java 风格的类继承层次，常用组合表达复用关系。

```go
type User struct {
    ID   int64
    Name string
}

func (u User) DisplayName() string {
    return u.Name
}
```

值接收者会复制接收值，指针接收者可以修改原对象，也能避免复制较大的结构体。一个类型的方法集应保持一致而清晰。

## 接口由实现方隐式满足

Go 类型不需要显式声明实现了某个接口。只要方法集合匹配，就可以赋给该接口：

```go
type Store interface {
    Find(id int64) (User, error)
}
```

这让接口可以定义在使用方附近。小接口通常更易组合和测试，没必要提前为每个结构体创建庞大接口。

需要注意，接口值由动态类型和动态值组成。一个包含空指针的接口不一定等于 `nil`，这是常见边界问题。

## 错误是普通返回值

Go 通常显式返回 `error`：

```go
user, err := store.Find(id)
if err != nil {
    return User{}, fmt.Errorf("find user: %w", err)
}
```

调用者可以根据需要包装、判断或返回错误。错误信息应补充当前操作上下文，但不要重复记录并返回同一个错误，避免日志噪声。

`panic` 更适合不可恢复的程序错误，而不是常规业务分支。

## 零值是设计的一部分

许多 Go 类型的零值可以直接使用。设计自定义类型时，让零值具有合理语义可以减少构造样板。

切片、映射和通道虽然语法相近，零值行为并不相同：nil 切片可以读取和追加，nil 映射不能写入，nil 通道的收发会永久阻塞。需要分别理解。

## goroutine 不是线程池任务的同义词

goroutine 很轻量，由 Go 运行时调度。启动并发工作很简单：

```go
go handle(job)
```

但创建容易不等于无需治理。仍要考虑：

- 如何限制并发数量；
- 任务何时退出；
- 错误如何汇总；
- 超时和取消如何传递；
- 共享状态是否有竞态。

`context.Context` 常用于传递取消、截止时间和请求范围信息。它通常作为第一个参数逐层传递，不应存进长期存活的结构体字段。

## channel 用于通信，不替代所有锁

channel 适合表达任务传递、结果汇总和生命周期信号。互斥锁适合保护共享内存中的短临界区。选择取决于问题结构，而不是认为 channel 永远更高级。

无缓冲 channel 要求发送和接收会合；缓冲 channel 可以暂存有限元素。关闭 channel 表示不会再有新值，通常由发送方负责关闭。

## 工程工具形成统一约定

Go 自带格式化、测试和模块工具，团队通常保持统一格式而减少风格争论。包名应简短明确，导出标识符以大写字母开头，未导出标识符以小写开头。

测试文件与被测包放在相邻位置，以 `_test.go` 结尾。表驱动测试适合覆盖一组输入输出场景。

## 从 Java 迁移时的常见误区

- 用结构体和接口模拟复杂继承树；
- 为每个错误创建过重的类型层次；
- 无限制启动 goroutine；
- 把 `context` 当作通用参数容器；
- 忽略切片底层数组共享带来的修改影响；
- 依赖全局可变变量方便访问。

## 总结

Go 鼓励小接口、显式错误、组合和简单的工程约定。Java 经验依然有价值，但不需要把原有类层次和异常模型逐字翻译过来。先接受 Go 的惯用边界，代码通常会更直接。
