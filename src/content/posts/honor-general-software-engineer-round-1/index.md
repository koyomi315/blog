## 一、自我介绍与个人项目

1. 请做一下自我介绍，介绍你的技术方向、实习经历和个人项目。
   - 当时回答：主要方向是 Java 后端开发和 Agent 应用开发。实习参与内部 Agent 评测平台，介绍了自动评测任务、长链路异步任务的状态流转，以及高并发秒杀个人项目中的一人一单、防超卖和缓存问题。
2. 追问：这些项目是为了学习技术、锻炼能力而做的个人项目吗？
   - 当时回答：是为了学习相关技术栈、锻炼能力而完成的个人项目。

## 二、AI 辅助开发与个人能力

3. 做项目和学习时，你如何使用 AI？哪些环节会借助 AI 完成？
   - 当时回答：先区分项目本身使用大模型和用 AI 辅助研发。我会与 AI 讨论项目可以改进的地方和改进方式，后续很多编码由 AI 辅助完成，也会让它讲解不熟悉的知识。
4. 追问：大量代码由 AI 完成时，你怎么看自己的能力体现和成长？
   - 当时回答：AI 编程已经很常见，能力不只是知道函数、快速写代码；更重要的是理解业务需求，做技术选型和取舍，把 AI 当作工具，提升自己的决策能力。
5. 进一步追问：缺乏成熟项目经验时，如何判断 AI 提出的方案并做技术决策？
   - 当时回答：个人项目是在实习之前做的，确实缺少成熟经验。我会继续追问，了解自己想到的以及 AI 提出的备选技术方案，先学习、形成基本认识，再作决策。

## 三、实习项目与工具 Mock

6. 介绍实习中的 Agent 评测平台，以及你具体负责的工作。
   - 追问：评测的 Agent 做什么业务？平台主要给谁使用？
   - 当时回答：评测对象是商家入驻相关的业务 Agent，平台主要面向企业内部，帮助研发了解 Agent 的表现并进行优化。我主要承担自动评测任务和 Tool Mock 两项工作，参与需求理解、开发和交付上线。
7. 追问：你说的“模拟”具体模拟什么？工具 Mock 如何参与评测，为什么不用真实工具？
   - 当时回答：模拟的是工具调用，而不是整个 Agent。离线评测先重放 Agent，再评估其表现；重放中需要调用工具时，按工具、入参等匹配数据，返回模拟结果。真实工具可能访问数据库或创建业务数据，产生副作用；不同时间的工具结果还可能变化，引入无关变量，影响评测结果的可信度。

## 四、Java 并发与死锁场景

8. Java 对多线程并发有哪些保障？
   - 当时回答：重点关注多个线程并发读写共享资源导致的竞态问题，通过加锁控制访问。我提到了 `ReentrantLock` 和 `synchronized`，希望保证同一资源在同一时间只有一个线程访问。
9. 场景追问：A、B 两个资源，两个线程都需要使用；一个线程先占有 A，另一个先占有 B，随后彼此等待，导致死锁，应该怎么解决？
   - 当时思路：因为两段代码都由我们设计，可以统一资源获取顺序，要求先获取 A，再获取 B；如果没有获取 A，就等待，不继续获取 B。
   - 记录说明：这是当时给出的思路，没有记录进一步讨论或实际验证情况。

## 五、删除操作与中断恢复场景

10. 删除数据和相关索引涉及多个操作时，如何处理中途被打断的情况，保证操作完整？
    - 当时思路：我先澄清是否需要在删除数据的同时删除索引，然后借用事务的概念，提出记录每一步是否完成；中途打断后，恢复到之前的状态，或者继续完成尚未执行的操作。
    - 记录说明：具体删除对象、索引类型和中断方式未记录，保留这个概括题干，没有补成特定数据库或分布式事务题。

## 八、面试复盘：整理建议

以下是根据这场记录补充的事后建议，与当时回答分开：

- **AI 编程表达：** 准备一个真实的方案比较和验证案例，说明自己如何判断 AI 的建议、作出取舍并检查结果，让“决策能力”有具体经历支撑。
- **并发场景：** 回看 Java 并发保障的不同层面，不只列举锁的名称。死锁题先确认是在问预防还是处理已经发生的死锁；当时提出的统一加锁顺序主要用于预防，需要补练对已发生死锁的分析与处理。
- **恢复场景：** 在回答前明确删除对象、中断位置和要保证的结果，再讨论记录进度、恢复或继续执行。仅提到事务和步骤记录，还需要解释失败后如何保证操作完整。
