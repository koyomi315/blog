# 排版与内容规则

沿用博客当前 schema 和邻近文章风格。保留入口 skill 交接的技术原意、代码语义、事实与贡献边界；调整排版与结构，不大幅改写、扩写或虚构成果和数据。面经题意与实际回答以面经入口交接的最终稿为准。

新文章模板（替换示例值，日期使用 Asia/Hong_Kong 当天）：

学习文档和面经各使用入口 skill 自带的模板。示例字段按实际内容替换；不要将占位值写入最终文章。新面经分类为“面试记录”；学习文章按实际主题选分类。

`updated` 仅在已有文章正文或元数据有实质变化时设为当天；首次 `published` 不变。相同输入与既有内容无变化时，不为日期制造变更。新文缺省不加封面和作者栏，不填写内部生成的 prev/next 字段。

优先复用现有分类：后端开发、AI Agent、Agent Evaluation、技术探索、面试记录、博客导读；根据实际文章选择最合适的一项，必要时可新增明确分类。分类与标签自动汇总，无需修改导航或站点配置。

格式化要求：

- 独立 Markdown 模板和本地整理稿保留一个文章级 H1，且与 frontmatter 的 title 一致；引言后章节从 H2 开始。新发布文章由博客布局将 title 渲染为 H1，发布正文不再重复该标题；历史文章正文已有 H1 时，布局兼容保留其标题层级，避免额外生成第二个 H1。转换时仅移除与 title 一致的文章级 H1；其他 H1 按章节关系调整层级并保留内容。核对最终页面标题层级，不能把大字号的 div 当作 H1。
- 统一段落、列表、表格和代码块空行；代码围栏标注可确定的语言；保留公式、引用及参考来源，正确引用 YAML 字符串。
- 标准本地图片复制到文章目录，保持资源唯一且改写路径。将 Obsidian wikilink/嵌入改为博客可用的 Markdown。找不到图片时搜索源项目附件；仍缺失则报告具体引用并等待补充，不能伪造图片或悄悄删掉有意义的插图。
- 本批次文章间链接和已映射文章链接改为对应博客路由；锚点须与目标一致。源码链接可转成已核实的公开仓库链接，不能把源仓库相对路径直接带进博客。未发布笔记链接可保留链接文字并说明未公开；不扩大范围自动发布被链接文档。
- 检查内部平台地址、凭证和个人信息。普通内部导航链接可移除地址、保留技术描述；发现疑似凭证或无法判断是否可公开的实质内容时，准备好其余内容并请用户决定该处，再继续发布。
- 核对当前博客渲染支持；不能假定 Obsidian 或 Mermaid 语法可直接渲染。不能无损转换时说明具体问题，待解决后发布。

不要运行会改写整个 src 的 `pnpm format` 或 `pnpm lint`；仅格式化本次文章和资源。
