# 输入与发布映射

读取适用的目录说明、入口 skill 提供的稳定来源稿、博客 `src/content/config.ts` 和相近主题文章。学习来源的解析后真实路径须在 `E:/intern/intern-study/docs/` 内；面经来源为 `E:/intern/interview-experience/` 场次目录内的最终稿。面经目录可能不是 Git 仓库，不以此阻止读取；目标博客仍须核对仓库身份。路径失效时查明移动记录或询问，不猜测另一个文件。

映射沿用博客根目录 `.study-publish-map.json`，与文章同一次提交。该历史文件名同时记录学习文章和面经，不另建第二份映射。格式保持 `version: 1`：

```json
{
  "version": 1,
  "sources": {
    "docs/agent-study/RAG.md": {
      "post": "src/content/posts/rag-study/index.md"
    },
    "interview-experience/公司-岗位-轮次/面经.md": {
      "post": "src/content/posts/company-role-round-1/index.md"
    }
  }
}
```

键和值统一正斜杠，只更新本次条目，保留其他映射：

- 学习文档使用相对 intern-study 根目录的键，如 `docs/agent-study/RAG.md`。
- 面经使用 `interview-experience/<相对路径>`，包含场次目录与最终稿文件名。原始输入另由场次记录追踪；新流程以最终稿发布，不以每次新增附件创建来源身份。
- 值为相对 blog 根目录的文章路径。单篇源文使用 `{ "post": "..." }`；已有一份源文对应多篇的映射保持 `{ "posts": [{ "part": "稳定场次或分篇名称", "post": "..." }] }`。拆分时保留原 post 对应内容与路径，再转为 posts；新增部分只增加对应项，不因重排改变旧路径。

## 新建、更新与迁移

- 已有映射：更新原文章，保留路径、网址、首次 `published` 和用户维护的元数据。映射损坏或目标消失时先查明，不静默新建替代文章。
- 无映射：先搜索已有文章，只有确认为同一源文档的已发布版本才复用并补映射。主题相同不代表同一篇；面经还须核对公司、岗位、轮次、已知日期与题目。综合面经不能仅因分类相同就覆盖。无法区分重复文章与独立文章时列候选询问。
- 新文章使用 `src/content/posts/<简短英文-kebab-slug>/index.md`；历史中文单文件文章保持原路径。
- 源文件移动或历史来源从原始记录改为最终稿时，核对原文、最终稿与已有博客文章，再迁移原键并复用目标；同一篇只有一个当前来源键，不因来源迁移新建文章。
- 历史整理稿与博客有差异时保留各版本，记录差异及当前发布来源；仅修复路径不会授权覆盖博客正文。实际更新时再按本次范围核对内容。

仅整理模式不写正式映射。来源迁移的维护任务可以只修复本地映射，提交和推送依本次用户授权执行。
