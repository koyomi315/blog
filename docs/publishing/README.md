# 博客共享发布流程

本目录供两个业务 skill 共同读取：学习文章由 `intern-study` 的 `publish-study-to-blog` 整理，实际面经由 `interview-experience` 的 `interview-to-blog` 整理。这里负责博客排版、来源映射与 Git 发布，不负责教学、还原面试问题或归档私有原文。

## 交接与授权

业务 skill 交接时提供：内容类型（学习文章 / 面经）、稳定来源稿路径、本次文章范围、发布或仅整理模式，以及已经确认的内容边界。面经以本地最终 Markdown 稿作为来源，转写、音频和确认记录只用于核对，不进入博客。

目标仓库为 `E:/Code/blog`，预期 origin 为 `https://github.com/koyomi315/blog.git`，部署分支为 `main`。修改前核对实际仓库身份与适用说明。

发布授权沿用入口 skill 与本次用户指令；读取或修改这些说明本身不构成发布授权。仅整理模式保存在所属资料目录，完成内容检查后结束，不修改博客、正式发布映射或执行发布专用的同步、提交、推送。

## 执行入口

1. 发布模式先读取 [检查与 Git 发布](publishing.md)，完成修改前的状态检查。
2. 读取 [输入与发布映射](source-mapping.md)，确定既有目标或新文章路径。
3. 整理博客正文前读取 [排版与内容规则](editorial.md)。模板与业务内容规则由入口 skill 提供；保持其已确认的问题、实际回答、技术结论和贡献边界。
4. 按发布说明检查文章与资源、验证构建，只提交推送本次文章、资源与映射。遇到阻塞保留现场，报告稿件、提交和推送各自状态。

完成后向入口 skill 返回稳定来源、博客文章路径、分类、提交 SHA 和实际推送状态。部署成功需另有实际验证，推送成功只说明已触发部署。
